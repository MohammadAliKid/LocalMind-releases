Privacy Policy

LocalMind keeps a working library on your device. Connecting another service changes where some information goes. This policy explains those choices and their limits.

LocalMind is maintained by MohammadAliKid. There is no LocalMind-hosted notes database or central LocalMind account service. The maintainer does not automatically receive your note library. This policy covers the application and this public website.

Release scope: current public Windows and Android downloads are v0.6.8, which include the optional Google Drive connection described below. Earlier versions (v0.6.0 and older) have no Google Drive connection.

1. Your local library

Notes, collections, tags, history and flashcards live in a local SQLite library. Images are stored as local files. On Windows the default library is under %LOCALAPPDATA%\LocalMind, separate from the program installation. Android uses application storage. LocalMind does not require a Google or AI account for core note editing and local study.

The local notes database and ordinary image files are not encrypted by LocalMind. Device permissions, your operating system and any device encryption you enable protect those files. Drive encryption does not encrypt all local files, exports or operating-system backups.

2. Optional encrypted Google Drive synchronization

When you connect Drive, LocalMind requests only https://www.googleapis.com/auth/drive.appdata. This permits access to LocalMind's hidden application-data folder. It does not grant LocalMind general access to your Drive files, Gmail or contacts. LocalMind does not request additional profile or email scopes for this feature.

From version 0.6.8, LocalMind shows which Google account is connected. It reads that account's email address and display name through Drive's account-information request under the same drive.appdata permission (Android may also receive the email from Google Play services). The account email is kept only on your device, including next to any pairing code the device remembers so LocalMind can avoid syncing a library into the wrong account. It is not uploaded to the synchronized library, written to logs or included in bug reports.

LocalMind uploads and downloads change journals, workspace/device records and referenced images through that folder. It never synchronizes the active SQLite database. The synchronization carrier encrypts object contents with AES-256-GCM before upload and uses keyed, opaque filenames. The recovery key is not uploaded to Google Drive. Google still processes your account authorization, network requests, storage usage and object metadata such as sizes and update times.

You pair devices using the same Google account and a code containing the workspace identifier and recovery key. Anyone with that code and access to the account's encrypted library can decrypt it. Keep a separate private copy. LocalMind has no recovery-key escrow: losing the code and all configured devices can make the encrypted library unrecoverable.

Drive access is used for the synchronization and recovery features you enable. LocalMind does not sell your Drive data or send it to advertising platforms. Connecting Drive does not itself enable AI. If you separately use AI on a note, that feature may send its contents to the selected provider as described below.

Google processes Drive storage and account data under Google's Privacy Policy. Google documents its application-data folder and API Services User Data Policy. LocalMind's encryption is an application feature, not a claim that Google has approved, audited or certified LocalMind.

3. Google authorization and protected credentials

Desktop Google authorization opens Google's official page in your system browser and uses a state-checked authorization-code flow with PKCE and a local loopback callback. Android uses Google Play services authorization. LocalMind does not receive your Google password.

On Windows, Google refresh tokens and the recovery pairing key use Windows DPAPI for the signed-in Windows user; access tokens are cached in memory. Android relies on Google Play services for the authorization grant, keeps app access tokens in memory, and encrypts its recovery key with Android Keystore-backed storage. Keys are used in application memory while performing the functions they protect.

LocalMind's own note exports, note backups and synchronization journals exclude OAuth tokens, AI credentials and recovery keys. Android excludes its credential preferences from Android's cloud-backup and device-transfer rules. This does not mean that all application files are excluded from operating-system backups.

Disconnecting Drive keeps local notes and remote encrypted objects. From version 0.6.8, a device can also remember pairing codes it has used in the operating system's protected credential storage so you can reconnect later; you can choose to forget the code when disconnecting. Signing out forgets local authorization; revoking LocalMind's access is a separate option that also asks Google to remove the grant. If a network error prevents confirmation, revocation may still need to be completed in your Google Account connections. Revocation alone does not erase stored notes or encrypted Drive history.

4. Folder synchronization and backups

Syncthing or another shared-folder carrier is a separate option. LocalMind writes readable change-journal and media files to the folder you choose. Those folder files are not protected by LocalMind's Google Drive encryption. Protect the folder and review the synchronization tool's own settings and policies. The active SQLite database is not placed in the synchronization folder.

LocalMind's exports and automatic note backups can contain note text, history, flashcards and images. They are not password-encrypted by LocalMind. Files you export, shared folders, Windows/cloud backup software and Android system backups may create additional copies according to your choices and operating-system settings. Keep private backups in storage you control.

5. Optional AI providers

LocalMind can send information directly from your device to the provider you select when you invoke an AI feature or enable supported automatic organization. This can include note content and the context needed for the requested feature, such as collection/tag names, notes selected for a merge, or material used to generate flashcards or source-search suggestions. Your original notes are not silently replaced with AI output.

Provider availability varies by platform. Current options include OpenAI API/ChatGPT-plan access on supported desktop configurations, Google Gemini, OpenRouter, Anthropic, and a locally configured LM Studio server on supported desktop configurations. Android does not offer every desktop provider. A Drive authorization grant is separate from a Gemini API key.

Providers process requests under their own terms and account settings. Retention, human review and training practices can differ between free, paid and subscription services; some unpaid services may use submitted content to improve their products. OpenRouter can route a request to another model provider. LocalMind cannot promise that every provider deletes requests or excludes them from training. Check the in-app provider disclosure and your account controls before sending confidential content.

OpenAI Responses requests set store: false; that parameter is not a blanket guarantee of zero retention by every OpenAI service. LocalMind's own implementation does not run a model-training pipeline. AI credentials remain outside note exports and sync files. A local model connection stays on the configured loopback server, but you should review that server's own behavior.

6. Other services and device integrations

  • Anki: approved card content and related tags can be sent to AnkiConnect on your computer. Android can send approved Basic/Cloze cards to AnkiDroid after permission. Any Anki/AnkiDroid account or cloud synchronization is controlled by those products.
  • Sources: reviewed search terms, DOIs and reference URLs can be sent to OpenAlex, Wikipedia, Crossref or linked websites when you use source-search/update features. These services receive ordinary network metadata and the queries or URLs you submit.
  • Updates: GitHub serves public update metadata and binaries. Checks may run in the background when enabled. GitHub receives ordinary request metadata; LocalMind does not attach your note library or AI credentials to update checks.
  • Sharing and images: Android text shares, camera/gallery selections and explicit image-paste actions supply content you choose. A pending text share is saved locally so cancelling or restarting need not lose it. LocalMind does not continuously monitor the clipboard for the image-paste feature.

7. Retention, deletion and recovery limits

LocalMind retains local records until you remove them or clear the relevant application files. Notes have history and synchronization deletion records. Deleting a note marks it deleted; it is not a promise to securely erase every historical copy. Older revisions, images, exports, backups, encrypted Drive journals and other devices can retain information.

What you want to removeWhat to do
A note from the current libraryUse the note's delete action. Undo/history and synchronization records can remain.
Local Windows application dataClose LocalMind and remove the relevant LocalMind data/config files and separate backups. Uninstalling the Windows program does not remove its separate note library.
Android private application dataUse Android's app-storage controls or uninstall the app. Shared folders, exports, remote storage and OS backup copies require separate handling.
LocalMind's encrypted Drive libraryStop sync on your devices first. Use Google Drive Settings → Manage apps to remove LocalMind's hidden app data; wording may vary. There is no dedicated “Delete Drive data” control in this candidate. Deleting remote objects does not delete local libraries, and connected devices may otherwise upload again.
Google authorizationDisconnect/sign out in LocalMind and, if needed, remove access in Google Account connections. This does not itself delete stored data.

The maintainer cannot remotely retrieve, decrypt or erase your local library or your encrypted Drive library. Google and other service providers control retention within their services under their own policies. Deleting a file does not guarantee erasure from storage-device remnants or third-party backups.

8. Diagnostics and support

Application diagnostics are stored locally and may include timestamps, error codes, versions and file paths. Credential redaction is implemented, but you should inspect diagnostics before sharing them. LocalMind has no automatic application-analytics or crash-report upload service in this implementation.

If you voluntarily submit a support issue, attachment or message, the maintainer and the service you use receive that material. GitHub issues are public and follow GitHub's policies. Do not post notes, passwords, tokens or recovery keys in public support requests.

9. This website

This is a static website designed for GitHub Pages. It has no sign-in form, analytics scripts, advertising, tracking pixels or third-party fonts, and does not set application cookies. Hosting and DNS providers can process IP addresses and standard request logs under their own policies. Download links and external services have their own policies. See GitHub's Privacy Statement.

10. Contact and changes

Contact the maintainer through LocalMind's public support repository. For a sensitive privacy concern, request a private contact method without posting the sensitive material itself. The date at the top identifies this policy version. Material changes to how Google data is used should be disclosed before that new use is enabled, with renewed consent where required.
